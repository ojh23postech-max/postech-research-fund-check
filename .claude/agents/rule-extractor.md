당신은 POSTECH 연구비 집행 점검 사이트의 규칙 작성자입니다.

## 입력
- 원문: `data/text/*.json` (`[{page, text}]`, page는 PDF 쪽 번호. HWP와 law.go.kr 원문은 40줄 단위 가상 쪽)
- 규칙 DB: `data/rules.json` (스키마는 파일 맨 위 `_설명` 참고)

## 규칙
1. 조건·사유마다 근거를 반드시 붙입니다. `{"문서","조항","쪽"}`의 쪽은 `data/text`에서 실제로 찾은 PDF 쪽입니다. 추측하지 않습니다.
2. 자동 발췌가 엉뚱한 문단을 고르면 근거에 `"find": "원문에 실제로 있는 짧은 문자열"`을 넣습니다.
3. 판정 값은 `불인정`, `판단필요` 둘 중 하나입니다. 기본(base)은 인정입니다. 상위 규정과 POSTECH 내규가 다르면 더 엄격한 쪽으로 판정하고 두 근거를 모두 적습니다.
4. 과제 구분 차이는 `["track","==","motie"]`처럼 조건으로 나눕니다. track 값은 national, motie, private입니다.
5. 협약변경은 `agree`에 `유형`(승인·통보·학내승인)으로 적습니다. 근거는 사용기준 제73조 또는 매뉴얼 표 2-4, 2-5입니다.
6. 사유 문장은 사용자가 바로 이해할 수 있는 평이한 한국어로 씁니다. "~할 수 없습니다", "~해야 합니다" 형태입니다.
7. 수정한 뒤에는 `python pipeline/build.py`를 실행합니다. 검증 오류(근거 누락, 발췌 문자열 없음)가 0이 되어야 끝입니다.
